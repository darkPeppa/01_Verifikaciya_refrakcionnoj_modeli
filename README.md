# Задача 01. Верификация рефракционной модели рентгеновских преломляющих линз в Geant4

**XrayCRLGeant4** — программа на Geant4 для моделирования прохождения рентгеновского излучения через
составные преломляющие линзы (CRL) из ортогонально‑скрещённых линейных параболических элементов SU‑8
(объективы и конденсоры микроскопа МИР 15–35 кэВ). Проект к работе «Modelling the Interaction of Radiation
with Matter for Optimizing X‑ray Refractive Lenses» (Неустроева, Резникова, Назьмов, SKIF‑2026).

Что внутри:

* **Этап 1 — верификация рефракционной модели**: точная геометрия параболических поверхностей, собственный
  процесс преломления рентгеновских фотонов, фокусировка 4 конструкций таблицы 2 диссертации и вариантов
  объектива 2; 16 автоматических проверок + 10 юнит‑тестов (все PASS). Отчёт: `results/validation/validation_report.md`.
* **Этап 2 — физика взаимодействий в линзах** (включая плоскость перетяжки: сколько фотонов приходит в фокусное пятно, в шум и поглощается — при 25; 30,4; 30,6; 35 кэВ): фотоэффект, комптоновское и рэлеевское рассеяние, флуоресценция
  в тех же SU‑8 элементах; данные для всех массивов линз при 25 кэВ и сканирование через **K‑край сурьмы
  30,49 кэВ** (SU‑8 с Sb и без). Данные с подробными описаниями: папка **`data/`** (`data/README.md`).
* **Постер A1** с визуализацией моделирования: `poster/poster_A1.pdf` (для печати) и **`poster/poster_A1.pptx` — редактируемый в PowerPoint** (тексты, таблицы и диаграммы — родные объекты PowerPoint, данные диаграмм правятся через «Изменить данные»).

Уже посчитанные результаты лежат в архиве (`results/`, `data/`, `poster/`) — их можно смотреть сразу.
Ниже — как пересчитать всё самостоятельно на любом компьютере с Docker.

---

## 1. Что нужно

Только **Docker**. Всё остальное (Geant4 11.4.2 со всеми наборами данных, компилятор C++, CMake, Python,
numpy, matplotlib) ставится **автоматически внутри контейнера** при первом запуске, по зафиксированному
списку точных версий пакетов (`docker/conda-lock-*.txt`), поэтому результат одинаков на любой машине.

| | требование |
|---|---|
| ОС | Windows 10/11 (64‑бит), Linux, macOS (Intel или Apple Silicon) |
| Диск | ~8 ГБ свободно (образ ~4,5 ГБ + кэш) |
| Память | 4 ГБ RAM для Docker (по умолчанию в Docker Desktop хватает) |
| Сеть | только при первом запуске: скачивается ~2 ГБ (Geant4 и его данные) |
| Время | первая сборка 10–40 мин (зависит от интернета), затем полный расчёт ~35–45 мин; быстрая проверка ~5 мин |

## 2. Установка Docker

### Windows

1. Скачайте **Docker Desktop for Windows**: https://www.docker.com/products/docker-desktop/ и установите
   (галочка «Use WSL 2 instead of Hyper‑V» — оставить включённой).
2. Если установщик попросит — перезагрузите компьютер. Если появится сообщение про WSL 2, откройте
   «PowerShell» **от имени администратора** и выполните `wsl --install`, затем перезагрузитесь.
3. Запустите Docker Desktop и дождитесь внизу слева статуса **«Engine running»** (зелёный).
4. Убедитесь, что Docker работает с **Linux‑контейнерами** (по умолчанию так и есть; в меню значка Docker
   в трее не должно быть пункта «Switch to Linux containers…» — если он есть, нажмите его).

Если при запуске Docker пишет про виртуализацию: включите «Intel VT‑x / AMD‑V (SVM)» в BIOS/UEFI.

### macOS

Установите **Docker Desktop for Mac** (для Apple Silicon или Intel) с того же сайта, запустите его.

### Linux

Установите Docker Engine (https://docs.docker.com/engine/install/), добавьте пользователя в группу `docker`
(`sudo usermod -aG docker $USER`, затем перелогиньтесь) или запускайте скрипт через `sudo`.

## 3. Запуск

1. Распакуйте архив **в папку без кириллицы и пробелов в пути**, например `C:\work\task01`
   (на Windows это заметно надёжнее). 
2. Запустите расчёт:

### Windows

Двойной щелчок по **`run_windows.bat`** — выполнится полный расчёт. Окно не закроется само, в конце будет
написано «ГОТОВО» и путь к результатам.

Другие режимы — из командной строки (Win+R → `cmd` → перейти в папку проекта):

```
cd C:\work\task01
run_windows.bat quick
```

### Linux / macOS

```bash
cd ~/task01
./run.sh quick
```

### Режимы запуска

| команда | что делает | время* |
|---|---|---|
| `run_windows.bat` / `./run.sh` | всё: этап 1 (проверки + графики), этап 2 (данные), постер | ~40 мин |
| `… quick` | быстрая проверка всей цепочки (мало фотонов) — **запустите сначала её** | ~5 мин |
| `… validate` | только этап 1: 16 проверок рефракционной модели + графики | ~5 мин |
| `… stage2` | только этап 2: физика взаимодействий, папка `data` | ~35 мин |
| `… figures` | пересобрать каталог рисунков `data/figures` | 1 мин |
| `… poster` | постер (нужны результаты validate и stage2 в том же запуске — используйте полный режим) | 1 мин |
| `… unit` | юнит‑тесты C++ | секунды |
| `… calc --config config/runs/<файл>.json [--set ключ=значение]…` | один расчёт с вашими параметрами | секунды–минуты |
| `… shell` | командная строка внутри контейнера (для экспериментов) | — |

\* после первой сборки образа; на обычном ноутбуке.

При каждом запуске скрипт сначала собирает образ (`docker build`). В первый раз это долго (скачивание и
компиляция), дальше — несколько секунд из кэша. Во время сборки программа компилируется и проходит
юнит‑тесты — если сборка дошла до конца, программа работает.

## 4. Где результаты

Все результаты запуска копируются в папку **`output/`** рядом со скриптом (готовые результаты из архива в
`results/`, `data/`, `poster/` при этом не перезаписываются — их можно сравнить):

| путь | содержание |
|---|---|
| `output/results/validation/validation_report.md` | отчёт этапа 1: таблица всех проверок PASS/FAIL, фокусы, сравнение с табл. 2 |
| `output/results/figures/*.png, *.pdf` | графики этапа 1 (ход лучей, RMS, фокусы, f(N), тесселяция, Снеллиус) |
| `output/data/` | данные этапа 2 + `README.md` с описанием каждого файла и колонки |
| `output/data/figures/` | **все рисунки проекта (этап 1 и 2) в одной папке**: пронумерованы, с подписью «Рис. N» на изображении (PNG) + векторные PDF; список подписей — `FIGURES.md` |
| `output/poster/poster_A1.pdf` | постер A1 (вектор, для печати), `poster_A1.png` — превью; `poster_A1.pptx` — редактируемый (если в окружении есть python-pptx; готовый лежит в `poster/`) |
| `output/results/<имя>/` | результаты ваших расчётов `calc` |

Файлы `.csv.gz` — сжатые CSV: открываются в Python (`pandas.read_csv("файл.csv.gz")`), Origin, 7‑Zip, Excel после
распаковки.

## 5. Свои расчёты

Все параметры — в текстовых JSON‑файлах (`config/`), перекомпиляция не нужна:

* `config/materials/su8.json` — плотность, элементный состав, модель δ(E);
  `su8_noSb.json` — контрольный состав без сурьмы;
* `config/lenses/*.json` — линзы табл. 2 (R, A, N, p, d, L, табличные фокусы);
* `config/runs/*.json` — сценарии: линза + режим + источник + вывод.

Любой параметр меняется ключом `--set` (значение в формате JSON; строки — в кавычках). Примеры:

```
run_windows.bat calc --config config/runs/objective1_full_paraxial.json --set source.energy_keV=30
run_windows.bat calc --config config/runs/condenser2_full_grid.json --set physics.em="livermore" --set source.mode="random" --set source.n_random=20000
run_windows.bat calc --config config/runs/objective1_full_paraxial.json --set system.N_per_axis=100
run_windows.bat calc --config config/runs/objective1_full_paraxial.json --set material="../materials/su8_noSb.json" --set physics.em="livermore" --set source.mode="random" --set source.energy_keV=30.6
```

(В `./run.sh` — то же, строковые значения в одинарных кавычках: `--set 'physics.em="livermore"'`.)

Если вы изменили файлы в `config/` — просто запустите скрипт снова: образ пересоберётся за секунды.

Основные ключи сценария:

| ключ | значения |
|---|---|
| `system.mode` | `single` (1 элемент), `pair` (X+Y), `full` (весь набор 2N), `slab` (плоская пластина); `system.N_per_axis` — своё N |
| `physics.em` | `none` — только преломление (этап 1), `livermore` / `penelope` / `option4` — с физикой взаимодействий |
| `physics.fluo` | флуоресценция (по умолчанию `true`) |
| `refraction.enabled`, `refraction.delta_override` | включить/выключить преломление; заменить δ константой |
| `source.energy_keV` | энергия фотонов |
| `source.mode` | `paraxial` (пары лучей для фокуса), `grid` (сетка n×n), `random` (равномерно), `fan_x`/`fan_y` (веер), `axis` |
| `source.n_random`, `source.grid_n`, `source.aperture_fraction`, `source.seed` | число лучей, размер сетки, доля апертуры, зерно |
| `source.divergence_urad` | угловой разброс пучка [σx, σy], мкрад (конечный источник) |
| `geometry.surface` | `analytic` (точные параболы) или `tessellated` (ломаная, `geometry.segments` хорд) |
| `output.trace_events` | сколько фотонов записывать с полной траекторией |

Выходные файлы одного расчёта (`output/results/<имя>/<имя>_*`): `_summary.json` (всё главное: фокусы тремя
методами, аналитика, судьба фотонов, μ), `_rays.csv` (каждый фотон), `_interactions.csv` (каждое
взаимодействие), `_trace.csv` (траектории), `_geometry.csv`, `_rms.csv`, `_element_profile.csv`,
`_secondaries_exit.csv`. Описание колонок — в `data/README.md`.

## 6. Если что‑то пошло не так

| симптом | что делать |
|---|---|
| «Docker не запущен» | запустите Docker Desktop, дождитесь «Engine running» |
| `docker: command not found` / «не является внутренней командой» | Docker не установлен или не перезапущена командная строка после установки |
| ошибка при скачивании (`failed to fetch`, `connection reset`) | проблема сети/прокси: повторите запуск (скачанное сохраняется); за корпоративным прокси настройте его в Docker Desktop → Settings → Resources → Proxies |
| «no space left on device» | освободите место; Docker Desktop → Troubleshoot → Clean / Purge data, или `docker system prune` |
| «image operating system "linux" cannot be used on this platform» | Docker в режиме Windows‑контейнеров: переключите на Linux‑контейнеры (меню значка Docker) |
| WSL 2 / виртуализация | `wsl --install` в PowerShell от администратора; включите виртуализацию в BIOS |
| расчёт очень долгий | закройте тяжёлые программы; в Docker Desktop → Settings → Resources дайте Docker больше CPU |
| хочется начать с чистого листа | удалите папку `output` и образ: `docker rmi refraction-task01:1.0` |

Проверено: сборка образа и полный расчёт на Linux ARM64 (Apple Silicon, Docker Desktop) и Linux x86‑64
(тот же тип окружения, что Docker Desktop на Windows) — см. раздел «Проверка переносимости» в
`docs/VALIDATION.md`.

## 8. Без Docker (для разработчиков)

Нужны Geant4 11.x (проверено на 11.4.2), CMake ≥ 3.16, C++17, nlohmann_json, Python 3 + numpy + matplotlib:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j
build/unit_tests
OUT=$PWD/out bash scripts/entry.sh all        # то же, что делает контейнер (пишет в ./out)
```

## 9. Ограничения и следующие шаги

* Геометрическая оптика: дифракция, интерференция и функция рассеяния точки не моделируются; размер пятна
  оценивается формулой (5.2.5) и расходимостью источника.
* Параметры источника СКИФ не заданы — пучок параллельный (или с иллюстративной расходимостью).
* δ(E) ∝ E⁻² — без аномальной дисперсии у K‑края Sb (влияние на фокус ~0,2 %, см. `data/README.md`).
* Высота структур и рамка элементов не указаны в источниках — параметры.

Дальше: дифракционный расчёт PSF и разрешения, реальный источник СКИФ и монохроматор, погрешности
изготовления (смещения, наклоны, ошибки R и d), сравнение материалов, конденсор + объектив МИР вместе.
